Endorsement Policies (§2)

  • MintPropertyTokens: AND('OriginatorMSP.peer','RegistrarMSP.peer') — prevents unilateral minting
  • TransferTokens: InvestorMSP sender only — regulator as non-endorsing observer
  • FreezeAsset: RegulatorMSP only — emergency action
  • Chaincode also checks MSP at function level (defense in depth)

Edge Cases Implemented (§6)

Tokenization

  • Registrar rejects → status REJECTED, resubmit as new asset version
  • Duplicate property → hash index collision flagged, allowed but flagged
  • Double mint → status check + existing balance check + idempotency key
  • Valuation change after mint → not allowed v1 (phase-2 governance)
  • Supply overflow → capped at 10M, int64 check

Transfer

  • Insufficient balance → ERR_INSUFFICIENT_BALANCE, no partial
  • Self-transfer → ERR_INVALID_TRANSFER
  • Unverified KYC → ERR_KYC_NOT_VERIFIED (gateway + chaincode)
  • Zero/negative → ERR_INVALID_AMOUNT
  • Concurrent double-spend → Fabric MVCC auto-rejects second tx
  • Frozen asset → check status != FROZEN
  • Network partition → atomic per-block, client polls transferId
  • Fractional → integer-only tokens, 1 token = valuation/totalTokens

Identity & Access

  • Revoked cert → Fabric CA revocation list checked at endorsement
  • Regulator write attempt → allow-list per function, ERR_UNAUTHORIZED
  • KYC change after holding → existing balance unaffected, new transfers blocked
  • Lost key → custodian org phase-2 (demat model)

Data Integrity

  • Off-chain doc tampered → recomputed hash vs on-chain documentHash mismatch → UI warning, requires regulator review
  • Schema change → versioned composite keys + migration chaincode, never mutate TransferRecord
  • Clock skew → block timestamp (orderer-assigned), not peer clock
